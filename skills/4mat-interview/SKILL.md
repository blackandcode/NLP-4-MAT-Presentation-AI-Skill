# 4MAT interview (the reusable interactive primitive)

Read source content and prior answers first. Fill S1–S8 as E/I/M using the main orchestrator scheme; never re-ask explicit answers. Ask only currently unblocked decisions, at most **3** related questions per interaction. If the native `AskUserQuestion` tool exists, use it for selections; otherwise provide 2–4 numbered choices and an Other option. Explain a recommendation in one sentence, not a lecture. Accept terse answers like `A`, `2`, `you decide`, `skip`, or `custom`.

**Round 1: Decide the change.** Offer outcome types: (A) academic understanding and defensible claims, (B) fund/approve/pilot decision, (C) teach a reusable skill, (D) inspire a community or parent group. Ask for audience with concrete role and familiarity, not unverified 'learner types'; duration and medium if absent. Separate the presenter objective from audience outcome.

**Round 2: Why this audience cares.** Derive verified pain, values and interests from supplied material; distinguish inferred from stated concerns. Offer story options: A personal mission (requires user authorization), B identifiable audience problem (with real example), C future contrast (clearly hypothetical). Ask one preference only when it changes the storyboard.

**Round 3: Demonstration and future.** Match format: live demo; narrated walkthrough; audience experiment; no-tool operational example. Decide risks/upside and the final requested action. Ask a secondary accessibility or tone preference only if material.

Stop when S1, S2, S3, S5–S7 are explicit or deliberately assumed, not after an arbitrary question count. Write a compact `brief.md` containing: topic, audience segment and prior knowledge, presentation goal, observable outcome, presenter intent, time, medium, language, must-include facts/claims, story strategy, HOW medium, closing action, accessibility needs, non-goals, open assumptions. User can revise any entry. Do not interpret silence as consent for controversial claims.
